# 交付规范（需求分析报告 · 全组必读）

本目录是各组员交付任务的统一位置。**一人一个文件夹，只动自己的文件夹。**

## 目录结构

文件夹命名：**`编号-模块名-姓名`**（编号 1~4 见下表，姓名用真实姓名），如 `1-账户管理-张三`。

```
docs/交付/
  README.md                    ← 本文件（组长维护）
  1-账户管理-成员B/             ← 示例：含「用户登录」完整演示（"成员B"为占位，待换真实姓名）
    用户登录.md                 ← 一个用例一个 md：功能描述 + 逻辑分析与建模
    用户注册.md
    images/                    ← 本人的所有图片（PNG + 同名 .html 源文件一起提交）
      账户管理模块用例图.png / .html
      用户登录_活动图.png / .html
      用户登录_类模型图.png / .html
      用户登录_协作图.png / .html
  2-相册管理-姓名/
  3-照片管理-姓名/
  4-类别与评论-姓名/
```

| 编号 | 模块 | 文件夹 | 负责用例 |
|------|------|--------|----------|
| 1 | 账户管理 | `1-账户管理-姓名/` | 用户注册、用户登录 |
| 2 | 相册管理 | `2-相册管理-姓名/` | 创建相册、修改相册 |
| 3 | 照片管理 | `3-照片管理-姓名/` | 上传图片、浏览照片 |
| 4 | 类别与评论 | `4-类别与评论-姓名/` | 相册类别管理、对照片评论 |

## 每个用例的 md 写什么

照 `1-账户管理-成员B/用户登录.md` 的结构来（这是已完成的完整演示），两大部分：

1. **功能描述**：用例描述（六段式：用例名称、参与者、前置条件、基本流程、扩展流程、后置条件）→ 用例图（模块级，同一模块两个用例共用一张）→ 活动图。每幅图后面必须配文字说明。
2. **逻辑分析与建模**：类模型图（边界/控制/实体三类）→ 协作图（消息按用例执行顺序编号）。同样每图配说明。

## 画图流程（各自本机完成）

1. 使用 diagram-design skill（已安装在项目 `.kimi/skills/diagram-design/`）绘制自包含 HTML 图稿，黑白风格，遵守 `docs/绘图规范.md`（走线不穿框、扩展流程必须画成分支）。
2. 图稿源文件为与 PNG 同名的 `.html`（内联 SVG），由自己的构建脚本生成、脚本自行保管；改图改脚本重新生成，不手改 HTML。
3. 导出 PNG（2 倍缩放），可用 Chrome 无头截图或 skill 自带导出流程。
4. 交付前对每幅 HTML 跑 skill 校验（`scripts/self_check.py` + 几何校验），**导出后逐张目检**：无穿框、无压字、无错位、文字完整，再提交。

## 命名约定

- 交付文件夹：`编号-模块名-姓名`，编号 1~4 按上表，姓名为真实姓名。
- 图片文件名不含图编号（如 `用户登录_活动图.png`）；图编号（图 2-x）由组长整合排版时统一添加，不要烤进图片。
- 图片源文件（与 PNG 同名的 `.html`，diagram-design skill 产出的自包含 HTML）与 PNG 一起提交，方便他人后续修改。
- md 中引用图片一律用相对路径，这样在 GitHub 上能直接渲染。写法示例（放在代码块里防转义）：

  ```
  ![用户登录_活动图](images/用户登录_活动图.png)
  ```

## Git 协作流程

1. 组长把本仓库推到 GitHub（私有仓库），把组员加为 collaborator。
2. 每人拉取后创建自己的分支，分支名：`成员X-模块名`（如 `成员B-账户管理`）。
3. 在自己的分支上只提交 `docs/交付/自己的文件夹/` 下的内容；公共文件（本 README、`AGENTS.md`、`docs/需求分析/`、`tools/`、`docs/绘图规范.md`）由组长统一维护，**不要改**。
4. 完成后向 `main` 发 Pull Request，组长对照下方自查清单 review，通过后合并。
5. 合并后组长统一整合进报告 Word 模板、统一图编号。

## 提交前自查清单

- [ ] 用例描述六段式齐全，与 `docs/需求分析/02_用例描述初稿.md` 口径一致（如有修改要说明理由）
- [ ] 每个用例：活动图 1 张；每个模块：用例图 1 张；每个用例：类模型图 + 协作图各 1 张
- [ ] 活动图覆盖全部扩展流程，错误分支画成回路（拐回对应步骤）
- [ ] 协作图消息按执行顺序编号，与用例基本流程一一对应
- [ ] 协作图对象框内不写冒号；双向消息画成两条平行线、各自带箭头，编号标签紧贴所属线段
- [ ] 类模型图类框为三栏矩形拼接（类名/属性/方法，不用灰色分隔线）；同一关联线的关联名与两端多重性统一放在线的同一侧（水平线在上方、垂直线在侧方）
- [ ] 每幅图后面有文字说明（画了什么 + 为什么这样设计），不允许只贴图
- [ ] PNG 已逐张目检：无穿框、无压字、文字完整
- [ ] 图片源文件（同名 `.html`）已一并提交
- [ ] 图片引用为相对路径，GitHub 上能正常显示
