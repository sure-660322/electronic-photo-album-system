# 电子相册系统面向对象设计 · 公共设计约定

本文件为账户管理、相册管理、照片管理、评论与点赞四个模块提供共用的设计约定。功能范围和业务流程沿用[面向对象需求分析报告](../需求分析/03_完整需求分析报告.md)中的九个用例。下文给出的字段长度、接口路径和错误码用于各模块对齐实现。

## 1. 权限表

| 操作 | 访客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 注册、登录 | 可注册普通账户，使用已有凭据登录 | 共用登录入口 | 使用预置账户，共用登录入口 |
| 读取相册类别 | — | 可读取 | 可读取 |
| 浏览公开相册及其中的照片 | — | 可浏览 | 可浏览 |
| 浏览私有相册及其中的照片 | — | 限本人相册 | 限本人相册 |
| 创建相册 | — | 可创建，所有者为当前用户 | — |
| 修改相册、上传图片 | — | 限本人相册 | — |
| 发表评论、点赞、取消点赞 | — | 限可访问的照片，点赞操作限本人记录 | — |
| 删除评论 | — | 限可访问照片中的本人评论 | — |
| 新增、修改、删除类别 | — | — | 可维护，仍被相册引用的类别禁止删除 |

- 登录角色取自账户记录。注册时服务端固定写入 `member`，管理员账户由初始化数据提供。
- 相册对登录用户可见的条件为「公开，或当前用户为所有者」。相册列表、照片列表、照片详情、原图、缩略图以及评论和点赞操作使用同一规则。打开编辑或上传入口时检查归属，提交时再检查一次。
- 相册所有者、图片上传者、评论作者和点赞用户均由服务端根据当前身份填写。管理员权限用于类别维护，浏览时适用相同的相册可见性规则。

## 2. 模块职责

Vue 页面对应 MVC 的视图，负责表单、跳转和状态展示。FastAPI 路由对应控制层，负责解析请求、获取当前身份、调用业务服务和返回 HTTP 响应。业务服务、SQLAlchemy 实体及其持久化操作属于模型层。数据库保存结构化数据，`uploads/` 保存原图和缩略图。

| 模块 | 覆盖用例 | 职责和依赖 |
| --- | --- | --- |
| 账户管理 | 用户注册、用户登录 | 校验注册信息、保存密码哈希、验证登录凭据、建立登录状态，并为各模块提供当前身份和角色。前端根据返回角色进入个人主页或类别管理后台。 |
| 相册管理 | 创建相册、修改相册、相册类别管理 | 维护相册名称、类别与可见性，提供类别列表和相册查询。创建与修改时校验类别是否存在，删除类别时处理相册引用关系。 |
| 照片管理 | 上传图片、浏览照片 | 负责文件校验、原图保存、缩略图生成、照片元数据写入，以及相册内照片列表、详情和图片读取。详情返回评论及点赞状态。 |
| 评论与点赞 | 对照片评论、对照片点赞 | 负责发布和删除本人评论、点赞和取消点赞。使用照片所属相册的访问规则，并按点赞记录计算数量和本人状态。 |

访问规则由相册管理模块中的 `AlbumAccessPolicy` 提供。照片管理和评论与点赞模块通过该策略检查访问权限。数据库事务由执行写操作的业务服务管理。

## 3. 设计类清单

### 3.1 领域实体

| 类 | 职责 | 关联 |
| --- | --- | --- |
| `User` | 记录账户资料、密码哈希及角色。 | 一个用户可以拥有多个相册，上传多张照片，发表多条评论并产生多条点赞。 |
| `Category` | 表示可供相册选择的类别。 | 一个类别可被零个或多个相册引用。 |
| `Album` | 记录相册名称、所有者、类别和可见性。 | 每个相册有一个所有者和一个类别，可包含零张或多张照片。 |
| `Photo` | 记录照片归属、上传者、原图及缩略图元数据。 | 每张照片属于一个相册，由一个用户上传，可关联多条评论和点赞。 |
| `Comment` | 记录评论正文、作者和发表时间。 | 每条评论关联一张照片和一个作者。 |
| `PhotoLike` | 记录某个用户对一张照片的点赞及时间。 | 每条点赞关联一个用户和一张照片，用户与照片的组合唯一。 |

`User.role` 区分普通用户和管理员。领域实体的属性、类型和约束见第 4 节。

### 3.2 服务与协作对象

下表列出关键方法。受保护操作的 `actor` 为服务端解析出的当前 `User`，`data` 为第 5 节对应的请求数据。

| 类 | 关键方法 | 职责 |
| --- | --- | --- |
| `AccountService` | `register(data) → User`、`authenticate(data) → User`、`issue_token(user) → str`、`resolve_user(token) → User` | 校验表单和凭据，保存或验证密码哈希，签发登录令牌并从有效令牌解析当前账户。 |
| `AlbumAccessPolicy` | `require_visible(actor, album_id) → Album`、`require_owned(actor, album_id) → Album` | 提供统一的可见性和归属判断，查询结果作为后续操作的相册。 |
| `AlbumService` | `list_albums(actor, scope) → list[Album]`、`get_album(actor, album_id, scope) → Album`、`create(actor, data) → Album`、`update(actor, album_id, data) → Album` | 查询本人或可见相册，创建与修改相册，校验名称、类别和可见性。列表查询与单条查询采用相同的权限规则。 |
| `CategoryService` | `list_categories() → list[Category]`、`create(actor, data) → Category`、`update(actor, category_id, data) → Category`、`delete(actor, category_id) → None` | 查询类别，验证管理员角色，维护类别名称和引用关系。 |
| `PhotoService` | `upload(actor, album_id, file, upload_id) → tuple[Photo, bool]`、`list_photos(actor, album_id) → list[Photo]`、`get_detail(actor, photo_id) → PhotoDetail`、`open_image(actor, photo_id, variant) → ImageStream` | 上传返回照片及是否新建，路由据此选择成功状态码。详情汇总照片、评论与点赞数据，读取图片时按所属相册校验可见性。 |
| `LocalPhotoStorage` | `save(path, stream) → None`、`open(path) → ImageStream`、`remove(path) → None` | 在 `uploads/` 内读写和清理图片文件。由照片服务持有并调用。 |
| `CommentService` | `create(actor, photo_id, body) → Comment`、`delete(actor, photo_id, comment_id) → None` | 校验照片可见性和评论内容，按照片和评论标识定位记录，并检查删除者是否为作者。 |
| `LikeService` | `set_liked(actor, photo_id, liked) → LikeState` | 按期望状态新增或删除本人的点赞记录，返回本人状态和总数。 |

## 4. 数据字典

独立实体主键采用 PostgreSQL 生成的整数标识。下表字段均为非空，外键均引用对应实体表主键。时间使用 `timestamp with time zone`，由服务端或数据库生成，接口以 UTC 的 ISO 8601 格式返回。用户名、相册名和类别名在校验前去除首尾空白，用户名和类别名区分大小写查重。

| 表 | 字段与类型 | 约束与说明 |
| --- | --- | --- |
| `users` | `id integer`、`username varchar(32)`、`email varchar(254)`、`password_hash text`、`role varchar(16)`、`created_at timestamptz` | `id` 主键、`username` 唯一且为 1–32 字符，邮箱校验格式，密码保存带盐哈希，角色为 `member` 或 `admin`。 |
| `categories` | `id integer`、`name varchar(50)` | `id` 主键，`name` 唯一且为 1–50 字符。修改时允许保留本条记录原名。 |
| `albums` | `id integer`、`owner_id integer`、`category_id integer`、`name varchar(100)`、`visibility varchar(7)`、`version integer`、`created_at timestamptz`、`updated_at timestamptz` | `id` 主键，`owner_id → users.id`，`category_id → categories.id`。相册名为 1–100 字符，可见性为 `public` 或 `private`。`version` 从 1 开始，每次保存加 1。外键限制删除相册正在引用的类别。 |
| `photos` | `id integer`、`album_id integer`、`uploader_id integer`、`original_path text`、`thumbnail_path text`、`upload_id uuid`、`media_type varchar(32)`、`size_bytes integer`、`created_at timestamptz` | `id` 主键，`album_id → albums.id`，`uploader_id → users.id`。服务端生成相对 `uploads/` 的两条路径，按解码结果填写原图类型。原图大小为 1–10,000,000 字节。`(album_id, uploader_id, upload_id)` 联合唯一，标识一次上传。 |
| `comments` | `id integer`、`photo_id integer`、`user_id integer`、`body varchar(200)`、`created_at timestamptz` | `id` 主键，`photo_id → photos.id`，`user_id → users.id`。正文去除首尾空白后为 1–200 字符，页面按纯文本呈现。 |
| `photo_likes` | `user_id integer`、`photo_id integer`、`created_at timestamptz` | `(user_id, photo_id)` 为联合主键，两列分别引用 `users.id` 和 `photos.id`。数量按该照片的记录数计算。 |

相册按 `owner_id` 和 `category_id` 建索引，照片列表按 `album_id` 查询，评论列表按 `photo_id, created_at DESC, id DESC` 查询，点赞统计按 `photo_id` 查询。照片、评论和点赞为上述查询设置对应索引。

### 4.1 写入规则

- **类别引用**。相册创建或修改时检查类别，数据库外键处理提交时类别已被删除的情况。删除类别时由同一外键限制引用中的类别，接口返回对应业务错误。
- **相册更新**。按相册、所有者和表单版本号一次性更新记录并递增版本。旧版本返回 `409 ALBUM_VERSION_CONFLICT`。
- **图片保存**。照片服务在事务内按上传标识预留照片记录，保存原图和 PNG 缩略图后提交。重试沿用同一上传标识，已提交的上传直接返回已有照片。文件清理与启动核对见[上传图片](02_用例详细设计/照片管理/06_上传图片.md)。
- **点赞写入**。设为已点赞时尝试插入联合主键对应记录，已存在则保留原记录。设为未点赞时按该联合主键删除。写入后用同一次查询取得总数和本人状态，提交成功后返回。相同操作重复发起时保持相同的本人点赞状态。

## 5. 接口约定

### 5.1 通用规则

- 下表路径统一加 `/api`。请求和响应字段使用 `snake_case`。上传用 `multipart/form-data`，图片读取返回二进制，其他带正文的请求和响应使用 JSON。
- 本稿采用 JWT。登录后签发有过期时间的令牌，由浏览器通过作用域为 `/api` 的 HttpOnly Cookie 传递，设置 `SameSite=Lax`。开发时 Vue 通过同源代理访问 API，浏览器请求原图和缩略图时自动携带会话。服务端验证令牌并读取当前账户，写操作核对请求的 `Origin`。
- 列表响应使用 `{ "items": [...] }`，空列表返回 `{ "items": [] }`。相册和照片列表按标识倒序，类别按标识正序，评论按发表时间及标识倒序。
- 表单校验错误使用统一错误结构。前端根据 `field` 定位输入项，根据 `code` 处理类别失效等业务分支。

### 5.2 用例与接口

| 用例 | 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- | --- |
| 用户注册 | `POST /auth/register` | `username`、`password`、`password_confirmation`、`email`，两次密码一致，密码 8–128 字符 | `201`，`AccountView`，页面引导至登录 |
| 用户登录 | `POST /auth/login` | `username`、`password` | `200`，`AccountView` 并建立会话，页面按角色跳转 |
| 用户登录 | `GET /auth/me` | 当前会话 | `200`，`AccountView`，用于页面重新加载时恢复当前用户 |
| 创建相册、修改相册、相册类别管理 | `GET /categories` | 当前会话 | `200`，`CategoryView` 列表，用于类别下拉框和管理列表 |
| 创建相册 | `POST /albums` | `name`、`category_id`、`visibility` | `201`，`AlbumView` |
| 浏览照片、相册管理入口 | `GET /albums` | 查询参数 `scope=visible`（默认）或 `scope=mine` | `200`，`AlbumView` 列表，分别返回可见相册或本人相册 |
| 浏览照片、修改相册与上传入口 | `GET /albums/{album_id}` | 查询参数 `scope=visible`（默认）或 `scope=mine` | `200`，`AlbumView`，编辑或上传入口限普通用户并用 `mine` 检查归属 |
| 修改相册 | `PUT /albums/{album_id}` | 编辑表单的 `name`、`category_id`、`visibility` 及载入时的 `version` 全量提交 | `200`，更新后的 `AlbumView` |
| 相册类别管理 | `POST /categories` | `name` | `201`，`CategoryView` |
| 相册类别管理 | `PUT /categories/{category_id}` | `name` | `200`，更新后的 `CategoryView` |
| 相册类别管理 | `DELETE /categories/{category_id}` | 路径中的类别标识 | `204`，页面刷新类别列表 |
| 上传图片 | `POST /albums/{album_id}/photos` | 单个文件 `file` 和本次选择生成的 `upload_id` | `201` 新建或 `200` 返回已提交的 `PhotoView` |
| 浏览照片 | `GET /albums/{album_id}/photos` | 路径中的相册标识 | `200`，`PhotoView` 列表 |
| 浏览照片 | `GET /photos/{photo_id}` | 路径中的照片标识 | `200`，`PhotoDetail` |
| 浏览照片 | `GET /photos/{photo_id}/original` | 路径中的照片标识 | `200`，原图及对应媒体类型 |
| 浏览照片 | `GET /photos/{photo_id}/thumbnail` | 路径中的照片标识 | `200`，PNG 缩略图 |
| 对照片评论 | `POST /photos/{photo_id}/comments` | `body` | `201`，`CommentView`，页面加入新评论 |
| 对照片评论 | `DELETE /photos/{photo_id}/comments/{comment_id}` | 路径中的照片和评论标识，页面确认后发起 | `204`，页面重新读取照片详情并刷新评论列表 |
| 对照片点赞 | `PUT /photos/{photo_id}/like` | `liked: true` 表示点赞，`liked: false` 表示取消点赞 | `200`，`LikeState`，页面更新按钮和计数 |

### 5.3 响应对象

| 对象 | 字段 |
| --- | --- |
| `AccountView` | `id`、`username`、`email`、`role` |
| `UserSummary` | `id`、`username`，供照片上传者和评论作者展示 |
| `CategoryView` | `id`、`name` |
| `AlbumView` | `id`、`name`、`visibility`、`version`、`owner_id`、`category`（`CategoryView`）、`created_at`、`updated_at` |
| `PhotoView` | `id`、`album_id`、`uploader`（`UserSummary`）、`created_at`、`thumbnail_url` |
| `PhotoDetail` | `photo`（`PhotoView`）、`original_url`、`comments`（`CommentView[]`）、`like`（`LikeState`） |
| `CommentView` | `id`、`photo_id`、`author`（`UserSummary`）、`body`、`created_at` |
| `LikeState` | `liked: boolean`、`like_count: integer` |

图片 URL 指向第 5.2 节的读取接口。服务端在每次读取时检查相册当前可见性，图片响应使用 `Cache-Control: no-store`。

### 5.4 错误响应

统一结构为 `{ "error": { "code": "CATEGORY_IN_USE", "message": "该类别下存在相册，不能删除" } }`。字段级错误必须在 `error.field` 中返回请求字段名。用户名重名为 `username`，类别重名为 `name`，选择的类别失效为 `category_id`，图片内容与大小错误为 `file`。多个字段同时出错时返回其中一个，表单保留输入。整条请求或资源级错误省略 `field`。例如确认密码不符时返回 `422` 和 `{ "error": { "code": "VALIDATION_ERROR", "field": "password_confirmation", "message": "两次密码不一致" } }`。

| HTTP 状态 | 业务代码 | 适用情况 |
| --- | --- | --- |
| `401` | `AUTH_REQUIRED`、`INVALID_CREDENTIALS` | 会话缺失或过期，或登录用户名和密码验证失败。 |
| `403` | `ROLE_FORBIDDEN`、`COMMENT_NOT_OWNED`、`ORIGIN_FORBIDDEN` | 角色无权执行当前操作，试图删除可见照片下他人的评论，或写请求来源校验失败。 |
| `404` | `ALBUM_UNAVAILABLE`、`PHOTO_UNAVAILABLE`、`CATEGORY_NOT_FOUND`、`COMMENT_NOT_FOUND` | 相册不可见或不属于当前用户，照片不可访问，维护的类别不存在，或目标评论不在指定照片下。 |
| `409` | `USERNAME_TAKEN`、`CATEGORY_NAME_TAKEN`、`CATEGORY_IN_USE`、`CATEGORY_UNAVAILABLE`、`ALBUM_VERSION_CONFLICT` | 用户名或类别名称重复，类别仍被引用，相册表单选中的类别已失效或相册版本过期。版本冲突时重新读取本人相册。类别失效时保留表单其他字段并重新读取类别列表。 |
| `413` | `IMAGE_TOO_LARGE` | 图片超过 10 MB。 |
| `422` | `VALIDATION_ERROR`、`INVALID_IMAGE` | 请求字段校验失败，或图片格式不符、内容无法解码。 |
| `500` | `UPLOAD_FAILED`、`INTERNAL_ERROR` | 上传已确认失败，或系统内部错误。 |
| `503` | `UPLOAD_STATUS_UNKNOWN` | 提交结果暂时无法确认，恢复连接后使用原 `upload_id` 重试。 |

各用例共用以下处理。`AUTH_REQUIRED` 引导重新登录，`ROLE_FORBIDDEN` 提示当前账户无权操作，`INTERNAL_ERROR` 提示稍后重试。写操作在确认事务失败时回滚。性能验收、文件核对与配套恢复见[系统验收与恢复设计](03_系统验收与恢复设计.md)。
