# 浏览照片 · 详细设计

模块为照片管理。已登录用户从浏览页选择相册，也可通过相册或照片链接直接访问。可见范围为他人公开相册和本人全部相册。设计依据为[浏览照片需求](../../../需求分析/03_完整需求分析报告.md#浏览照片)与[公共设计约定](../../01_公共设计约定.md)。

## 1. 接口与对象

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `GET /api/albums?scope=visible` | 当前会话 | `200`，可见相册的 `AlbumView` 列表 |
| `GET /api/albums/{album_id}` | 相册标识，默认 `scope=visible` | `200 AlbumView`，供进入相册页面时使用 |
| `GET /api/albums/{album_id}/photos` | 相册标识 | `200`，该相册的 `PhotoView` 列表 |
| `GET /api/photos/{photo_id}` | 照片标识 | `200 PhotoDetail`，含原图 URL、上传者、时间、评论和点赞状态 |
| `GET /api/photos/{photo_id}/original` | 照片标识 | `200`，原图及原图媒体类型 |
| `GET /api/photos/{photo_id}/thumbnail` | 照片标识 | `200`，PNG 缩略图 |

| 对象 | 职责 |
| --- | --- |
| Vue 浏览页、相册页、照片详情页 | 展示相册列表、缩略图网格和大图详情，处理空列表与不可访问状态。 |
| `AlbumService`、`AlbumAccessPolicy` | 通过 `list_albums(actor, scope)` 和 `get_album(actor, album_id, scope)` 提供相册入口，并统一判断相册可见性。 |
| `PhotoService` | 通过 `list_photos`、`get_detail` 和 `open_image` 读取照片。详情查询汇总 `Photo`、`User`、`Comment` 和 `PhotoLike` 的数据。 |
| `LocalPhotoStorage` | 接收照片记录中的相对路径，打开指定原图或缩略图。 |

## 2. 调用流程

1. 浏览页请求 `scope=visible`，服务按“公开或归当前用户”筛选相册并按标识倒序返回。可见相册为空时显示“暂无相册”。
2. 用户选择相册或打开相册链接，服务检查目标相册可见性。页面随后读取该相册的照片列表。照片列表接口也执行 `require_visible`，返回按标识倒序排列的 `PhotoView`。空列表显示“暂无照片”。
3. 相册页取得照片列表后，浏览器按各项的 `thumbnail_url` 请求缩略图并显示网格。
4. 用户点击缩略图进入详情。通过照片链接直接打开时，从本步开始。服务按 `photo_id` 查到照片，再通过其 `album_id` 检查当前可见性。通过后返回照片及上传者、按时间和标识倒序的评论、点赞总数和当前用户的点赞状态。
5. 详情页按返回的 `original_url` 请求原图并展示。

缩略图和原图共用读取规则。每次图片请求都会独立检查会话与相册可见性，然后用 `LocalPhotoStorage.open(path)` 打开对应文件并流式返回。图片响应使用 `Cache-Control: no-store`。

## 3. 异常处理

| 情况 | 返回与界面行为 |
| --- | --- |
| 相册不存在或当前用户无权访问 | `404 ALBUM_UNAVAILABLE`，提示“相册不可访问”，返回可见相册列表。 |
| 照片不存在、所属相册不可见或目标文件缺失 | `404 PHOTO_UNAVAILABLE`。详情页提示“照片不可访问”并返回相册列表。单张网格缩略图加载失败时显示占位。 |

## 4. 结果检查

- 所有者可查看自己的私有相册，其他普通用户和管理员访问该私有相册的详情及图片链接时被拒绝。
- 相册公开时可正常显示。改为私有后，其他用户重新发起的照片详情、原图和缩略图请求均返回 `404`。
- 全流程为读取操作，相册、照片、评论和点赞记录保持原状态。
