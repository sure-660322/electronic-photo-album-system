# 创建相册 · 详细设计

模块为相册管理。已登录的普通用户从“我的相册”进入创建页。设计依据为[创建相册需求](../../../需求分析/03_完整需求分析报告.md#创建相册)与[公共设计约定](../../01_公共设计约定.md)。

## 1. 接口与对象

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `GET /api/categories` | 当前会话 | `200`，返回供下拉框选择的 `CategoryView` 列表 |
| `POST /api/albums` | JSON 字段 `name`、`category_id`、`visibility` | `201 AlbumView` |
| `GET /api/albums?scope=mine` | 当前会话 | `200`，返回本人相册列表 |

| 对象 | 职责 |
| --- | --- |
| Vue 创建相册页 | 加载类别、提交表单、保留失败时的输入，成功后重新加载本人相册。 |
| FastAPI 相册路由 | 获取当前身份，解析表单，调用 `AlbumService.create(actor, data)`。 |
| `AlbumService`、`CategoryService` | 前者校验并新建相册，后者通过 `list_categories()` 提供当前类别列表。 |
| `Album`、`Category` | 保存相册及其类别引用。 |

## 2. 调用流程

1. 页面请求类别列表。有可选类别时显示相册名称、类别和公开或私有设置。类别列表为空时提示“暂无可用类别”，返回“我的相册”。
2. 用户提交表单。路由确认当前用户为 `member`，将当前用户和请求数据交给 `AlbumService.create`。
3. 服务去除名称首尾空白，校验名称为 1–100 字符、`category_id` 有效、`visibility` 为 `public` 或 `private`，并读取该 `Category`。
4. 服务构造 `Album`，将 `owner_id` 取自当前账户，填写名称、类别、可见性和创建、更新时间，将 `version` 初始化为 1。在事务中写入 `albums`，提交后返回新相册。
5. 页面提示创建成功，回到“我的相册”并重新读取列表。新相册按标识倒序展示。

## 3. 异常处理

| 情况 | 返回与界面行为 |
| --- | --- |
| 名称为空或过长、未选类别、可见性无效 | `422 VALIDATION_ERROR`，定位字段并保留当前表单。 |
| 所选类别已被删除 | `409 CATEGORY_UNAVAILABLE`，保留名称和可见性，重新读取类别并清除失效选项。刷新后无类别时提示并返回列表。 |

类别在校验后被删除时，由外键约束阻止写入，服务回滚后返回 `CATEGORY_UNAVAILABLE`。

## 4. 结果检查

- 新相册属于当前用户，类别与可见性和有效表单一致。
- 类别列表为空、类别失效或表单校验失败时，`albums` 无新增记录。
- 创建的私有相册出现在本人列表，其他用户的可见列表中无该相册。
