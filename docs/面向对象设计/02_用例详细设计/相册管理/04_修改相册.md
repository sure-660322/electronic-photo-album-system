# 修改相册 · 详细设计

模块为相册管理。已登录的普通用户从“我的相册”编辑本人相册的名称、类别或可见性。设计依据为[修改相册需求](../../../需求分析/03_完整需求分析报告.md#修改相册)与[公共设计约定](../../01_公共设计约定.md)。

## 1. 接口与对象

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `GET /api/albums/{album_id}?scope=mine` | 相册标识 | `200 AlbumView`，供表单回填 |
| `GET /api/categories` | 当前会话 | `200`，返回当前类别列表 |
| `PUT /api/albums/{album_id}` | 相册标识与表单的 `name`、`category_id`、`visibility` 及载入时的 `version` | `200 AlbumView`，返回修改后的相册 |
| `GET /api/albums?scope=mine` | 当前会话 | `200`，返回本人相册列表 |

| 对象 | 职责 |
| --- | --- |
| Vue 编辑相册页 | 加载原信息及类别、提交完整表单、保留修改内容并显示处理结果。 |
| FastAPI 相册路由 | 解析相册标识和表单，将读写操作交给 `AlbumService`。 |
| `AlbumService`、`AlbumAccessPolicy` | `get_album(actor, album_id, scope)` 读取表单数据，`update(actor, album_id, data)` 更新相册。两次操作均用 `require_owned(actor, album_id)` 检查归属。 |
| `Album`、`Category` | 保存相册属性，约束相册的类别引用。 |

## 2. 调用流程

1. 用户打开编辑页，路由检查普通用户角色，`AlbumService.get_album` 在 `scope=mine` 下确认归属。页面用返回的相册信息回填表单，保存本次读取的 `version` 并加载类别列表。
2. 用户提交名称、类别和可见性。路由再次确认角色，调用 `AlbumService.update`，服务按路径中的相册标识重新加载本人相册。
3. 服务去除名称首尾空白，校验名称为 1–100 字符、类别仍存在、可见性为 `public` 或 `private`。
4. 服务以 `id = album_id AND owner_id = actor.id AND version = 表单版本` 为条件，在同一条更新语句中保存名称、类别、可见性和更新时间，并令 `version = version + 1`。若影响零行，重新确认归属后区分相册不可用与版本冲突。成功提交后返回含新版本的 `AlbumView`。
5. 页面提示修改成功并返回“我的相册”。后续照片详情、原图和缩略图请求按更新后的可见性判定。

## 3. 异常处理

| 情况 | 返回与界面行为 |
| --- | --- |
| 入口或提交时相册不存在、相册不归当前用户 | `404 ALBUM_UNAVAILABLE`，提示“相册不存在或无权修改”并返回“我的相册”。 |
| 名称、类别字段或可见性无效 | `422 VALIDATION_ERROR`，提示修改对应字段，保留输入。 |
| 版本缺失或不是正整数 | `422 VALIDATION_ERROR`，`field=version`，重新载入编辑表单。 |
| 表单版本过期 | `409 ALBUM_VERSION_CONFLICT`。页面保存草稿并重新读取本人相册，以最新值回填。用户对照草稿重新选择要修改的字段后，用新版本提交。 |
| 选择的类别已失效 | `409 CATEGORY_UNAVAILABLE`，刷新类别列表，清除失效选项并保留其他修改。提交时触发类别外键约束也返回此错误。 |

## 4. 结果检查

- 两个标签页打开同一公开相册。A 页改为私有后，B 页用旧版本改名应收到 `409`，相册仍为私有。B 页重新载入后仅改名称，保存成功且可见性仍为私有。
- 修改名称和类别后，照片仍关联原相册，列表显示修改后的信息。
- 相册从公开改为私有后，其他用户重新访问原照片链接会被拒绝。
- 非所有者直接提交及类别失效时，原相册信息保持原值。
