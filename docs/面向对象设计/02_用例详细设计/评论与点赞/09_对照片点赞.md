# 对照片点赞 · 详细设计

模块为评论与点赞。已登录的普通用户可对可访问的照片点赞和取消点赞。设计依据为[对照片点赞需求](../../../需求分析/03_完整需求分析报告.md#对照片点赞)与[公共设计约定](../../01_公共设计约定.md)。

## 1. 接口与对象

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `GET /api/photos/{photo_id}` | 照片标识 | `200 PhotoDetail`，其中 `like` 包含本人状态与点赞总数 |
| `PUT /api/photos/{photo_id}/like` | 照片标识与布尔字段 `liked` | `200 LikeState`，包含 `liked` 与 `like_count` |

| 对象 | 职责 |
| --- | --- |
| Vue 照片详情页 | 显示点赞数量和本人状态，提交设为已点赞或未点赞的请求，根据回包刷新按钮。 |
| FastAPI 点赞路由 | 解析路径、布尔值和当前用户，调用 `LikeService.set_liked(actor, photo_id, liked)`。 |
| `LikeService`、`AlbumAccessPolicy` | 检查普通用户角色和照片可见性，写入本人点赞状态并重新统计。 |
| `PhotoLike` | 用 `(user_id, photo_id)` 联合主键表达点赞关系，记录创建时间。 |

## 2. 调用流程

1. 详情接口返回 `PhotoDetail.like`。前端根据 `liked` 显示“点赞”或“取消点赞”，同时显示 `like_count`。
2. 用户点击按钮后，页面提交明确的目标状态。点击“点赞”发送 `liked: true`，点击“取消点赞”发送 `liked: false`。当前请求返回前，该照片的按钮保持等待状态。
3. 服务检查角色和目标照片所属相册的当前可见性，以当前用户标识和路径中的照片标识作为联合键。
4. 在事务内处理写入。目标为已点赞时插入记录，发生联合主键冲突时沿用现有记录及其创建时间。目标为未点赞时按联合键删除，记录已不存在时操作完成。
5. 同一查询从该照片的记录中取得总数和本人状态，事务提交后返回 `LikeState`。页面用成功回包更新按钮和计数。请求失败时保留最近一次确认的状态并恢复按钮。

## 3. 异常与重复请求

| 情况 | 返回与界面行为 |
| --- | --- |
| `liked` 缺失或类型不符 | `422 VALIDATION_ERROR`，保持当前展示。 |
| 照片不存在或当前不可见 | `404 PHOTO_UNAVAILABLE`，提示“照片不可访问”，结束操作。 |
| 连续点赞或连续取消 | 每次成功返回 `200 LikeState`。本人状态保持请求指定的值，总数以各次查询时的实际记录为准。 |

## 4. 结果检查

- 同一用户对同一照片重复或并发点赞时，数据库最多保留一条记录。
- 两个用户各自点赞后，计数显示两条。任一用户取消后，另一用户的点赞记录保留。
- 取消已经取消的点赞仍返回 `liked: false`。重新打开详情时，状态与实际记录一致。
