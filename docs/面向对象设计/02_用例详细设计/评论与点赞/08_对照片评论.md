# 对照片评论 · 详细设计

模块为评论与点赞。已登录的普通用户在可访问的照片详情页发表评论，也可删除本人评论。设计依据为[对照片评论需求](../../../需求分析/03_完整需求分析报告.md#对照片评论)与[公共设计约定](../../01_公共设计约定.md)。

## 1. 接口与对象

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `GET /api/photos/{photo_id}` | 照片标识 | `200 PhotoDetail`，含按时间倒序排列的评论 |
| `POST /api/photos/{photo_id}/comments` | 照片标识与 JSON 字段 `body` | `201 CommentView`，加入评论列表 |
| `DELETE /api/photos/{photo_id}/comments/{comment_id}` | 照片及评论标识 | `204`，随后重新读取详情并刷新评论列表 |

| 对象 | 职责 |
| --- | --- |
| Vue 照片详情页 | 展示评论与输入框，按作者判断是否显示删除入口，删除前向用户确认。 |
| FastAPI 评论路由 | 解析当前身份和参数，调用 `CommentService.create(actor, photo_id, body)` 或 `delete(actor, photo_id, comment_id)`。 |
| `CommentService`、`AlbumAccessPolicy` | 检查普通用户角色、照片当前可见性、评论内容或评论归属，提交写入。 |
| `Comment`、`Photo`、`User` | 将一条评论关联到目标照片及当前作者。 |

## 2. 调用流程

1. 打开照片详情，页面从 `PhotoDetail.comments` 展示已有评论，通过 `author.id` 与当前账户标识判断是否显示相应评论的删除入口。
2. **发表评论**。页面提交正文。服务按照片记录的 `album_id` 检查可见性，去除正文首尾空白并校验 1–200 字符。在事务中写入 `photo_id`、当前用户的 `user_id`、正文和创建时间。提交成功后返回新评论。
3. 页面将返回的评论加入列表，按发表时间和标识倒序展示。正文以纯文本呈现，成功后清空输入框。
4. **删除评论**。用户点击删除，取消确认时结束操作，确认后发起请求。服务检查照片可见性，并使用路径中的照片标识和评论标识定位记录，再确认记录的 `user_id` 等于当前用户。
5. 确认为本人评论时，在事务内删除记录，提交后返回 `204`。页面重新请求 `GET /api/photos/{photo_id}`，用返回的 `comments` 替换整个评论列表。刷新失败时提示重新加载，重试仅执行读取。

## 3. 异常处理

| 情况 | 返回与界面行为 |
| --- | --- |
| 正文为空或超过 200 字符 | `422 VALIDATION_ERROR`，定位 `body`，保留输入并提示修改。 |
| 照片不存在或已不可见 | `404 PHOTO_UNAVAILABLE`，提示“照片不可访问”，结束当前操作。 |
| 评论不存在或属于另一张照片 | `404 COMMENT_NOT_FOUND`，页面通过详情接口更新评论列表。 |
| 评论属于其他用户 | `403 COMMENT_NOT_OWNED`，提示“只能删除本人评论”。 |

## 4. 结果检查

- 合规评论关联当前账号和目标照片，显示作者与发表时间，列表次序和详情接口一致。
- 取消删除、删除他人评论或使用另一张照片的评论标识时，目标记录保持原状态。
- 甲打开详情后，乙发表一条评论。甲删除本人旧评论，自动刷新的列表应显示乙的新评论，并移除甲的旧评论。
