# 用户登录 · 详细设计

模块为账户管理。普通用户与管理员共用登录页，管理员使用预置账户。设计依据为[用户登录需求](../../../需求分析/03_完整需求分析报告.md#用户登录)与[公共设计约定](../../01_公共设计约定.md)。

## 1. 接口与对象

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `POST /api/auth/login` | JSON 字段 `username`、`password` | `200 AccountView`，浏览器接收会话 Cookie |
| `GET /api/auth/me` | 当前会话 Cookie | `200 AccountView`，供刷新页面时恢复身份 |

| 对象 | 职责 |
| --- | --- |
| Vue 登录页和路由 | 提交凭据，根据 `role` 跳转，页面刷新时查询当前账户。 |
| FastAPI 认证路由 | 调用账户服务验证凭据、设置 Cookie，返回账户视图。 |
| `AccountService`、`User` | 通过 `authenticate(data)` 对照 `users` 校验凭据，通过 `issue_token(user)` 和 `resolve_user(token)` 建立、解析登录身份。 |

## 2. 调用流程

1. 用户提交用户名和密码。路由检查必填字段，服务按注册规则去除用户名首尾空白，按原值校验密码。
2. `AccountService.authenticate` 按用户名读取 `User`，验证输入密码与已保存的带盐哈希。验证通过后取该账户的当前角色。
3. `AccountService.issue_token` 签发 JWT，使用账户标识作为 `sub`，写入签发和到期时间。会话有效期由服务端统一配置，默认两小时。
4. 路由在响应中设置 `album_session` Cookie，使用 `HttpOnly`、`SameSite=Lax` 和 `Path=/api`，有效期与令牌一致。随后返回 `AccountView`。Vue 将 `member` 引导至个人主页，将 `admin` 引导至类别管理后台。
5. 页面刷新、进入受保护页面或发送受保护 API 请求时，服务端通过 `resolve_user` 校验令牌签名和有效期，再按 `sub` 读取当前账户。页面刷新时通过 `GET /api/auth/me` 获取同一账户视图。

## 3. 异常处理

| 情况 | 返回与界面行为 |
| --- | --- |
| 用户名或密码为空 | `422 VALIDATION_ERROR`，提示补全对应字段。 |
| 用户名不存在或密码错误 | `401 INVALID_CREDENTIALS`，统一提示“用户名或密码错误”，停留在登录页。 |
| 会话缺失、无效、过期或对应账户不存在 | 受保护接口返回 `401 AUTH_REQUIRED`。页面清除当前账户视图，提示登录。 |

## 4. 结果检查

- 普通账户和预置管理员使用同一个登录接口，成功后进入各自页面。
- 成功登录后刷新页面能恢复身份。令牌过期后，同一受保护接口返回 `401 AUTH_REQUIRED`。
- 登录读取现有账户记录，保持 `users` 中的角色及账户资料。
