# 用户注册 · 详细设计

模块为账户管理。参与者为访客，入口为注册页。设计依据为[用户注册需求](../../../需求分析/03_完整需求分析报告.md#用户注册)与[公共设计约定](../../01_公共设计约定.md)。

## 1. 接口与对象

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `POST /api/auth/register` | JSON 字段 `username`、`password`、`password_confirmation`、`email` | `201 AccountView`，页面提示注册成功并跳转登录页 |

| 对象 | 职责 |
| --- | --- |
| Vue 注册页 | 收集输入，展示对应字段的错误，成功后跳转。 |
| FastAPI 注册路由 | 解析提交数据，调用 `AccountService.register(data)`，将返回的 `User` 转为 `AccountView`。 |
| `AccountService`、`User` | 完成校验、密码哈希和账户写入，使用 `users.username` 唯一约束处理重名。 |

## 2. 调用流程

1. 访客填写四个字段后提交。页面先检查空值和两次密码是否一致，服务端执行最终校验。
2. `AccountService.register` 去除用户名首尾空白，检查用户名为 1–32 字符、邮箱格式及长度、密码为 8–128 字符。密码与确认密码按原值比较。
3. 服务按处理后的用户名查询 `users`。用户名可用时，对密码生成带盐哈希，构造角色为 `member` 的 `User`。
4. 在同一事务内写入用户名、邮箱、密码哈希、角色和创建时间。事务提交后，路由返回 `AccountView` 的 `id`、`username`、`email`、`role`。
5. 页面显示成功提示并进入登录页。用户随后通过[用户登录](02_用户登录.md)流程建立会话。

## 3. 异常处理

| 情况 | 返回与界面行为 |
| --- | --- |
| 必填项缺失、长度或格式无效 | `422 VALIDATION_ERROR`，定位对应字段，保留表单供修改。 |
| 两次密码不一致 | `422 VALIDATION_ERROR`，`field=password_confirmation`，提示重新确认。 |
| 用户名已存在 | `409 USERNAME_TAKEN`，提示该用户名已被占用。并发注册触发用户名唯一约束时，回滚后返回同一错误。 |

## 4. 结果检查

- 使用合法表单注册后应新增一条 `member` 账户，数据库保存密码哈希，回包仅包含账户视图字段。
- 两个请求同时注册同一个用户名时，数据库最多新增一条账户记录。
- 空字段、密码不一致或邮箱无效时，账户表无新增记录。
