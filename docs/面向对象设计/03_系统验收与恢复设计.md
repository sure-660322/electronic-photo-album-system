# 电子相册系统验收与恢复设计

本节对应[需求分析报告的非功能需求](../需求分析/03_完整需求分析报告.md#非功能需求)，用于系统实现后的本机验收。接口、表和响应对象见[公共设计约定](01_公共设计约定.md)。

## 1. 性能验收

使用本机 Vue、FastAPI、PostgreSQL 容器和本地图片存储。准备 20 个普通账户、本人相册、可见照片和一组已知大小的 JPEG、PNG、GIF 样例。记录运行环境、样例大小、库中相册与照片数量，便于复测。

| 场景 | 请求和结果检查 | 指标 |
| --- | --- | --- |
| 登录、相册列表、照片详情、评论、点赞 | 分别验证登录角色、列表可见性、详情字段、评论成功写入、点赞状态与数量。点赞交替提交两种状态。 | 各场景至少 95% 的有效请求在 2 秒内正确完成 |
| 上传单张合规图片 | 每次发起独立上传，样例覆盖接近 10 MB 的图片。检查成功回包及照片记录、原图和缩略图。 | 至少 95% 的有效请求在 5 秒内正确完成上传 |

1. 每个场景预热后，以 20 个并发用户持续发起请求，每个用户完成 5 次正式请求，合计 100 次。受保护接口使用各用户独立的登录状态。每次正式上传使用新的上传标识。
2. 从客户端发起请求计时至完整响应到达。上传计时包含传输、图片处理和数据库提交，回包后的文件核对另行执行。
3. 每个场景分别记录请求总数、成功数、失败数、成功请求的第 95 百分位耗时，以及达标数。以“结果正确且在时限内的请求数 / 全部正式请求数”判定，每组 100 次至少 95 次达标。错误和超时计入分母。

## 2. 上传中断后的启动核对

本机服务启动时，由单个维护进程在接收上传请求前完成核对。手动执行核对时先暂停写入、等待在途上传结束，并确认上一次服务连接的数据库事务已结束。照片表和文件目录在核对期间保持同一状态。

| 记录与文件状态 | 处理 |
| --- | --- |
| 记录引用的原图和缩略图均存在 | 保留文件，核对原图字节数和两条相对路径。 |
| 服务生成的上传目录没有任何照片记录引用 | 将该目录移至本地恢复隔离区，记录原相对路径。此目录退出在线存储，复查后可清理。 |
| 记录存在，但文件缺失、大小异常或路径不一致 | 记录照片标识和受影响路径，通过配套备份恢复对应文件并复核。 |
| 数据库暂不可读或只能读取部分记录 | 保留文件，待数据库恢复后重新执行完整核对。 |

扫描限于 `uploads/albums/{album_id}/{file_key}/` 内由服务生成的目录。先读取全部已提交照片的两个路径，再匹配目录。重复执行时，已匹配的照片和文件保持一致。

## 3. 配套备份与恢复

1. **取得一致的备份**。暂停全部业务写入，等待在途写事务和启动核对结束。完成文件与记录核对后，在同一备份批次中导出 PostgreSQL 数据库并复制 `uploads/`。两项都成功后恢复写入。
2. **记录备份内容**。保存批次标识、导出时间、照片记录数、数据库导出文件的 SHA-256，以及上传文件的相对路径、字节数和 SHA-256。核验记录与文件清单后将批次标记为完整。备份存放在项目仓库之外。
3. **恢复演练**。选取同一完整批次，将数据库导入独立测试库，图片还原到独立目录。核对导出文件和图片的校验值，逐条检查照片记录对应的原图、缩略图和字节数，并核对是否有未被引用的上传目录。
4. **业务复核**。使用恢复后的数据登录，打开公开照片及本人私有照片，读取原图、缩略图、评论和点赞数。另一账户访问前述私有照片应收到 `404`。记录备份批次、核对数量、差异和业务检查结果；正式恢复时在这些检查通过后重新开放写入。
