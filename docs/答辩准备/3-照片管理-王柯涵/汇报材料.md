## 第一页 功能需求与典型流程

### 页标题

照片管理：上传图片与浏览照片

### 一句话结论

登录用户在已有相册中上传受格式与大小约束的图片，并只能浏览公开相册或本人相册。

### 上屏要点

- 照片管理让登录用户把图片收入相册，并查看全站可浏览的照片。
- 上传图片：普通用户向已有相册添加新照片。
- 浏览照片：普通用户浏览公开相册与本人全部相册。
- 上传仅支持 jpg/png/gif，且不超过 10MB。
- 他人私有相册不可查看，链接直达同样要过权限校验。

### 典型流程与异常

- 典型用例：上传图片
- 前置条件：用户已登录，目标相册已存在
- 主流程：
  1. 进入目标相册，点击"上传图片"；
  2. 系统显示文件选择窗口；
  3. 选择本地图片文件并提交；
  4. 系统校验格式（jpg/png/gif）与大小（不超过 10MB）；
  5. 校验通过后保存文件、生成缩略图，并记录上传者与上传时间。
- 关键异常分支：格式或大小不符，提示"仅支持 jpg/png/gif，且不超过 10MB"，返回步骤 3 重新选择文件
- 操作后的结果：相册中新增一张照片，记录上传者、所属相册、上传时间

### 讲解稿

上传发生在已有相册内。用户选择图片并提交后，系统先检查格式为 jpg、png 或 gif，大小不超过 10MB，通过才保存文件、生成缩略图，并记录上传者与时间；不通过则提示限制，返回文件选择，不新增照片记录。图片文件保存在本机 uploads/，数据库只记录路径与元数据。浏览时，列表显示公开相册和本人全部相册，进入相册后查看缩略图，再点击查看大图及评论。即使通过链接直达他人私有相册，也必须经过同一个访问权限判断；无权查看时返回列表，链接不能绕过权限。

## 第二页 逻辑分析与建模

### 页标题

上传图片的类模型与对象协作

### 一句话结论

上传按“上传页面—上传控制器—照片”的分析职责协作，先校验格式与大小，再保存文件和照片元数据。

### 上屏要点

- 边界类上传页面：选文件、显示提示与结果。
- 控制类上传控制器：校验格式与大小、保存与生成缩略图、记录上传信息。
- 实体类照片：保存文件路径与元数据。
- 控制器—照片关联的照片端为 0..*：多次上传，每次新增一张。
- 校验不通过时，保存类消息全部不发生。

### 分析类与职责

- 边界类：上传页面（属性：上传表单；方法：显示文件选择窗口()、提示错误信息()、显示上传结果()）
- 控制类：上传控制器（方法：校验格式与大小()、保存文件并生成缩略图()、记录上传信息()）
- 实体类：照片（字段：照片编号、文件路径、缩略图路径、所属相册、上传者、上传时间；方法：保存()、获取详情()）
- 划分理由：页面只负责人机交互，不含业务规则；校验、保存、记录这些业务规则集中在控制器，便于统一修改；文件路径与元数据是需要长期保留的数据，归照片实体保存

### 关键关系

- 上传控制器 —照片，"创建并保存"关联，照片端多重性 0..*：控制器可处理多次上传，每次成功上传新增一张照片，单次上传失败不产生照片。
- 上传页面 —上传控制器，"提交上传请求"关联：交互与业务分离，页面调整不影响校验与保存逻辑。

### 协作消息

1. 消息 1 普通用户 → 上传页面：进入相册并选择文件
2. 消息 2 上传页面 → 上传控制器：提交文件并校验（校验格式与大小）
3. 消息 3 上传控制器 → 照片：保存文件/缩略图及信息（保存()，记录上传者与时间）
4. 消息 4 照片 → 上传控制器：返回保存结果
5. 消息 5、6 沿"上传控制器 → 上传页面 → 普通用户"逐层返回并提示上传结果
- 异常说明：消息 2 校验不通过时，成功路径的消息 3—6 不发生（不保存、不生成缩略图、不新增照片记录），页面改走"提示错误信息()"显示限制并回到文件选择。

### 讲解稿

上传分为三个分析类：上传页面负责文件选择和提示；上传控制器协调格式与大小校验、文件保存、缩略图生成及上传信息记录；照片实体保存路径、所属相册、上传者与时间等元数据。照片端的零到多表示控制器可处理多次上传，每次成功新增一张照片。协作图中，消息一选择文件，二提交并校验，三保存，四返回保存结果，五、六逐层提示结果。若校验不通过，就不进入成功路径的三到六，改为提示限制并重新选择。这里描述的是需求分析中的处理顺序，具体实现与运行效果仍待开发验证。

## 答辩问答

1. 业务/权限问题：浏览照片能看到哪些相册？拿到他人私有相册的链接直达会怎样？
   答：可见范围是所有公开相册加本人全部相册（含本人私有相册）。链接直达不绕过检查：访问请求与正常入口汇入同一个"相册可查看？"权限判断，他人私有相册会提示"该相册为私有，无权查看"并返回列表。
2. 建模问题：为什么照片端多重性是 0..*？照片实体里为什么只存路径不存图片本身？
   答：上传控制器可处理多次上传，每次成功上传新增一张照片，所以控制器—照片关联的照片端为 0..*。按需求阶段的存储约定，图片文件保存在存储区，照片实体只记录文件路径、缩略图路径等元数据，数据库不保存图片内容，便于以后演进为独立文件存储。
3. 异常流程问题：上传超过 10MB 或格式不符的文件会发生什么？
   答：系统在保存前校验格式与大小，不通过就不执行保存和缩略图生成，也不新增照片记录；提示"仅支持 jpg/png/gif，且不超过 10MB"并返回文件选择窗口，用户可重新选择。对应协作图中成功路径的消息 3—6 不发生。
