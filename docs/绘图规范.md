# 绘图规范（全组统一 · v2.1）

适用于本项目中所有报告图稿：体系结构图、功能框架图、用例图、活动图、类模型图、协作图。

> **v2 修订（2026-10）**：统一视觉基线与版面预算，替换 v1 的"纯黑白"约定。
> **v2.1**：新增两线交叉的跨越符号（小半圆桥），并规定活动图角色分流"先展开、后向下"的画法。
> v1 的结构规则（走线不穿框、扩展流程画分支、类框三栏、协作图编号等）全部继续有效。
> 图 2-1、图 2-2 也要按 v2.1 重出，否则报告里会同时出现两代风格。

## 1. 工具与流程

- 图稿由 Python 脚本生成 `.drawio`，**不手改 XML**。
- 公共样式集中在 `tools/figstyle.py`（色板、字体、线宽、类框、标签、折线、跨越符号），各人脚本通过相对路径引用，不再各写一套常量：

  ```python
  import sys
  from pathlib import Path
  ROOT = Path(__file__).resolve().parents[3]   # 脚本 → 模块目录 → 交付 → docs → 项目根
  sys.path.insert(0, str(ROOT / "tools"))
  import figstyle as fs
  ```

- 导出 PNG（以下命令都在项目根目录执行；把 `drawio` 换成本机 draw.io 可执行文件路径，`<模块>` 换成自己的文件夹）：
  ```
  drawio -x -f png --scale 2 -o "docs/交付/<模块>/images/xxx.png" "docs/交付/<模块>/images/xxx.drawio"
  ```
  本机没装 draw.io 时用应急渲染器（几何与 `.drawio` 一致，仅用于这条链路走通）：
  ```
  python tools/render_drawio.py "docs/交付/<模块>/images"
  ```
- 每张图导出后统一跑后处理（裁白边、补 32px、打印字号预算）：
  ```
  python tools/postprocess_png.py "docs/交付/<模块>/images"
  ```
- 最后逐张目检（第 8 节）。
- `tools/` 下的公共脚本由组长维护；成员自己的画图脚本放在自己的交付目录，不要改 `tools/`。各工具的作用与状态见 `tools/README.md`。

## 2. 视觉基线

### 2.1 色板（全组只用这 7 个色值）

| 用途 | 色值 | 用在哪里 |
|---|---|---|
| 主色 | `#2F5D8A` | 框线、主流程、用例椭圆、类框线 |
| 主色浅填充 | `#E9F0F8` | 系统处理动作、类名栏、页面/控制器对象框 |
| 容器填充 / 描边 | `#F5F8FB` / `#B7C7D6` | 系统边界、泳道式容器 |
| 异常强调 / 浅填充 | `#B4532A` / `#FBEFEA` | 扩展流程提示框（只配虚线使用） |
| 正文 / 次要文字 | `#1F2A35` / `#6B7C8C` | 正文；容器名、图注性文字 |
| 连线 | `#4A5A6A` | 所有连线 |

原则：

- **颜色只表达"分类"**（边界/控制/实体、系统处理、扩展异常），不表达"重要程度"。
- 灰度打印后必须仍能靠填充深浅和虚线区分——颜色不是唯一信息载体。
- 不使用阴影、渐变、3D、图标包、大面积彩色填充；学术报告要克制。

### 2.2 字体与字号

- 字体统一 Microsoft YaHei（`fontFamily=Microsoft YaHei`）。
- 正文/动作框/用例名 **14**；连线标签与多重性 **12**；类名 **14 粗体**；容器名 14、次要色。
- 类模型图属性/方法 13，行距按 24。
- 不在图内写图题（图号图名由 Word 排版添加）。

### 2.3 描边、圆角、箭头

- 框线 1.5；扩展/异常虚线 1.2；类框栏间分隔线与连线同为 1.5（同图线宽不超过两档）。
- 动作框圆角 10%；类框直角；对象框圆角 10%。
- 箭头：流程/消息 `block` 实心（size 7）；关联 `open` 空心（size 9）；参与者—用例无箭头。
- 开始=实心圆、结束=同心圆（外圈 2.5 描边）。
- **跨越符号**：两条线交叉时，在被跨越的那条线（一般是较上层的线）上画半径 6px 的小半圆桥；同一交叉点只画一个桥，另一条线保持连续。
- **拆段画桥**：为了在交叉处留缺口而把一条线拆成多段时，跨越段用 `SEG_JUMP`，其余过渡段用 `SEG_JUMP_NONE`（无箭头），箭头只保留在真正指向目标的那一段，避免转角处多出箭头。

### 2.4 留白与对齐

- 画布四周留 24px；后处理再统一补 32px，保证全报告图边距一致。
- 同类图元尺寸误差 ≤ 4px；同一列/主轴对齐；元素间距 ≥ 24px。
- 标签与线、框的距离 ≥ 6px；标签白底衬字，压线时必须衬白。

## 3. 版面预算（硬性，比配色更影响观感）

A4 纵向、左右各 2.7cm 页边距时，正文满宽约 15.5cm = 439pt。图内字号在 Word 里的实际大小：

```
满宽等效字号(pt) = 图内字号(px) × 439 / 内容宽度(px)
```

`tools/postprocess_png.py` 会按这个公式逐张打印结果。要求**正文 ≥ 8pt、标签 ≥ 7pt**。

| 图种 | 内容宽上限 | 正文字号 | 满宽等效字号 | 建议插入宽度 |
|---|---|---|---|---|
| 用例图 | 600 | 14 | 10.2pt | 12–15cm |
| 活动图 | 660 | 14 | 9.3pt | 12–15.5cm（竖长图） |
| 类模型图 | 760 | 13–14 | ≥ 8.1pt | 14–15.5cm |
| 协作图 | 700 | 14 | 8.8pt | 14–15.5cm |

补充约束：

- 活动图宽高比 ≤ 1.3（竖长，满宽插入后不超过一页）；协作图宽高比 ≤ 2.8（横长可整宽插入）。
- **宽度超标就重排，不许缩小字号、也不许把图缩得更小**：先减框宽、减间距、给长句换行。
- 协作图一律 ≤ 4 列对象；消息多的把实体放到第二行。

## 4. 走线规则（硬性）

- 连线不得穿越任何矩形框、不得压字、不得贴边（距框边 ≥ 6px）。
- 折线只走水平/垂直；进出框用固定锚点（边中点或明确的边上的点）。
- 回程/回流通道间距 ≥ 16px；**3 条以上回程线必须各走独立通道，不得共线或叠线**。
- 长绕线走图形外围通道，不横穿主体。
- **两线交叉处必须画跨越符号**（`jumpStyle=arc;jumpSize=6`，或统一画半径 6px 的小半圆桥），不允许裸交叉让人误以为是连接；同一交叉点只画一个桥（把其中一条线拆段，跨越段加跨越样式、过渡段用 `SEG_JUMP_NONE` 且不带箭头）。
- 连线标签放在自己那条线的外侧（水平线上方/下方、垂直线左方/右方），白底衬字，避开其它线。

## 5. 各类图的画法约定

**用例图**
- 小人 = 参与者（Actor），椭圆 = 用例，大矩形 = 系统边界（框名 = 系统名，左上角）。
- 边界 520×300 ~ 380×320，浅容器填充；用例椭圆 160×52，主色描边。
- 参与者—用例用实线、**不带箭头**；一个用例多个参与者时分别连线。
- 一个参与者服务两个用例时，把它放在两个用例的垂直中间，两条连线角度对称；只服务一个用例时与用例同高。
- **参与者小人保持原有 `umlActor` 图形（30×60），不换图标、不改画法**；只允许改线色。

**活动图**
- 圆角矩形 = 动作；菱形 = 判断（分支必须标"是/否"）；开始实心圆、结束同心圆。
- 基本流程单列自上而下，主轴固定，动作框同宽（建议 260–280）。
- 节点分类上色：用户动作=白底主色框；系统处理=浅主色填充；异常/提示=浅强调色虚线框；判断=白底菱形。
- 每个扩展流程都必须画成分支，处理后拐回对应步骤形成回路；回程线分通道，交叉处加跨越符号。
- 是/否标签放在线的外侧，**必须与用例描述语义一致**（例如"名称为空？"为"是"才提示错误）。
- 角色/条件分流的分支：先从判断菱形的左、右顶点向两边水平展开，再竖直向下指向对应动作框（每个分支只折一次），不要在框上方绕两次弯。

**类模型图**
- 类 = 三栏矩形：类名 / 属性 / 方法，由三个独立矩形拼接（共享边框），不用 `<hr>` 灰线。
- 类名栏浅主色填充、14 号粗体、带 «boundary»/«control»/«entity» 版型；属性/方法左对齐。
- 类框宽 210，**高度按内容自适应**（空属性栏保留一行，不留大片空白）。
- 关联带箭头（open）并标注两端多重性；关联名 + 两端多重性放线的同一侧：水平线在上方、垂直线在右方；多重性离端点 ≥ 10px。
- 边界/控制/实体三类齐全，类名、属性、方法与用例描述口径一致；同一实体在不同用例的图中字段保持一致。

**协作图**
- 对象框 150×50（消息多的可到 150×120），页面/控制器用浅主色填充，实体白底；参与者 30×60。
- 对象框内不写冒号（写「登录页面」，不写「:登录页面」）。
- 参与者名与用例描述一致（注册 = 访客，登录 = 登录者，涵盖普通用户与管理员；上传/浏览/评论 = 普通用户，类别管理 = 管理员）；实体对象名避开参与者名。登录协作图按账户角色展示对应页面，普通用户不进入后台。
- 每条消息一根独立直线段（两端坐标写死、不吸附图元）；双向消息画两条平行线，各带箭头，间距 ≥ 18px。
- 编号标签贴自己那根线（水平线上下方、垂直线左右方）；编号与基本流程一一对应。

## 6. 导出与后处理

- 一律 `--scale 2` 导出（打印要求高可用 3）；只导出内容，**不要整页导出带大块白边**。
- 统一跑 `tools/postprocess_png.py`：裁到内容、四周补 32px、白底 RGB，并打印"内容宽 / 宽高比 / 满宽等效字号"，不达标回改版面。
- 文件名不含图编号（编号由组长整合排版时统一添加）；`.drawio` 与 `.png` 同名一起提交。
- PNG 必须能由脚本一键重建；手工改图要同步改脚本。

## 7. 图题与编号

- 编号和图名**不烤进图片**，由排版同学在 Word 中图下方统一添加（如"图 2-1 系统体系结构图"）。
- 编号按章节：第 1 章系统目标，第 2 章功能需求。图 2-1 体系结构图、图 2-2 功能框架图，之后按报告顺序连续编号。
- 文件命名与图题一致：`图2-1_系统体系结构图.drawio` / `.png`。

## 8. 交付与自检

逐张核对，全部通过再交付：

- [ ] **数值**：内容宽不超上限；满宽等效字号 ≥ 8pt（标签 ≥ 7pt）；宽高比达标。
- [ ] **视觉**：无穿框、无压字、无贴边；四周边距一致；同类图元尺寸一致；色值不超过第 2.1 节的 7 个；灰度打印仍能区分主流程/异常/容器；两线交叉处有跨越符号、没有裸交叉。
- [ ] **逻辑**：用例、参与者、流程步骤与 `docs/需求分析/02_用例描述初稿.md` 一致；扩展流程无遗漏；活动图"是/否"与 md 文字描述一致；协作图编号与基本流程对应。
- [ ] **可复现**：改脚本 → 重生成 `.drawio` → 重导 PNG，三者同步。
- [ ] **说明**：每幅图后面都有文字说明（画了什么 + 为什么这样设计），不允许只贴图。
