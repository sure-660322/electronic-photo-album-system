# 绘图规范（全组统一）

适用于本项目中所有报告图稿：体系结构图、功能框架图、用例图、活动图、类模型图、协作图。

## 1. 工具

- 统一使用 **draw.io 桌面版**，每位组员在各自本机自行安装（官网 https://www.drawio.com/ 下载）。
- 图稿初稿由 `tools/` 下的 Python 脚本生成 `.drawio` 文件（参考 `tools/gen_login_demo.py`）；修改走脚本，不手改 XML。
- 命令行导出 PNG（2 倍缩放，把 `drawio` 换成本机 draw.io 可执行文件的实际路径）：
  ```
  drawio -x -f png --scale 2 -o 输出.png 输入.drawio
  ```
  Windows 示例：`"C:\Program Files\draw.io\draw.io.exe" -x -f png --scale 2 -o 输出.png 输入.drawio`
  （各人安装路径不同，不要把这个路径写死进任何项目文件。）

## 2. 风格

- **配色**：白底、黑白线条（`strokeColor=#444444`），不使用任何彩色主题。
- **字体**：图内文字统一 Microsoft YaHei 12 号；连线标签 11 号，白底衬字（`labelBackgroundColor=#FFFFFF`）。
- **层次填充**：只有最顶层框用浅灰 `#F5F5F5`，其余框白色。
- **虚线框语义**：表示"待定 / 扩展 / 可选"内容（如图 2-1 的后期存储方案、图 2-2 的扩展用例）。

## 3. 图题与编号

- 编号和图名**不烤进图片**，由排版同学在 Word 中图下方统一添加（如"图 2-1 系统体系结构图"）。
- 编号按章节：第 1 章系统目标，第 2 章功能需求。图 2-1 体系结构图、图 2-2 功能框架图，之后按报告顺序连续编号。
- 文件命名与图题一致：`图2-1_系统体系结构图.drawio` / `.png`。

## 4. 走线规则（硬性）

- **连线不得穿越任何矩形框**，也不得压字。
- 树状图（功能框架图）：横干线走上一层框的上方空隙，竖干线走列与列之间的间隙，从侧缘进出框。
- 分层图（体系结构图）：跨层连线从框的边中点进出；嵌套容器边界允许被"进出线"穿越，但不得斜穿。
- 连线标签放在线的上方，避开其他线和框。

## 5. 各类图的画法约定

**用例图**
- 小人 = 参与者（Actor），椭圆 = 用例，大矩形 = 系统边界（框名 = 系统名）。
- 参与者与用例之间用实线连接，**不带箭头**；一个用例有多个参与者时分别连线。

**活动图**
- 圆角矩形 = 动作/步骤；菱形 = 判断（分支必须标注"是/否"）。
- 开始 = 实心圆点，结束 = 同心圆。
- 基本流程自上而下顺序画；**每个扩展流程都必须画成分支**，不得遗漏。
- 异常/错误分支处理后必须拐回对应的步骤（如"返回输入"），形成回路。

**类模型图（阶段 3 使用）**
- 类 = 三栏矩形：类名 / 属性 / 方法，由三个独立矩形拼接（栏间共享黑边框），不用 `<hr>` 灰色分隔线；类间关系连线带箭头（关联、依赖、继承等）并标注多重性（如 1、0..*）。
- 同一关联线上的所有文字（关联名 + 两端多重性）全部放在线的同一侧：水平线统一在上方、垂直线统一在右方。

**协作图（阶段 3 使用）**
- 对象 = 方框，消息 = 带序号的箭头，按用例执行顺序编号（1、2、3……）。
- 对象框内不写冒号（写「登录页面」，不写「:登录页面」）。
- 每条消息一根独立直线段（两端坐标固定，不吸附图元），编号标签紧贴自己那根线（水平线标签在线上方/下方，垂直线标签在线的侧方）；双向消息画成两条平行线，方向一目了然。
- 参与者标注统一用用例描述中的参与者名（注册 = 访客，登录/评论 = 普通用户，类别管理 = 管理员）；实体对象命名避开参与者名，避免同名歧义（2026-09 修订）。

## 6. 交付与自检

- 导出 PNG 后必须**逐张目检**再交付：无穿框、无压字、无错位、文字完整。
- 每张图在报告中必须配文字说明（图里画了什么 + 设计意图），不允许只贴图。
